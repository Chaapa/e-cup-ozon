# E-CUP Quality — inference runtime

Директория содержит готовый runtime для двух категорий товаров.

## Контур принятия решения

- **БАД:** `Qwen/Qwen3.5-4B` на revision
  `851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a` запускается в BF16 через vLLM
  `0.26.0+cu129`. Два зафиксированных prompt дают first-token binary margins.
  Их сумма сравнивается с порогом `0.6875`; отдельно применяется узкое
  буквальное правило для явного `не БАД`.
- **Легковоспламеняющиеся:** итоговое решение формируют два CPU text expert,
  шесть зафиксированных LoRA checkpoints, CatBoost-selector, детерминированная
  rank quota и четыре sparse text gate.

Порядок входных строк сохраняется. Результат записывается в требуемом формате
`<комментарий>...<вердикт>...`.

После фиксации меток та же ordered vLLM-сессия строит комментарии с опорой на
фрагменты карточки для обеих категорий. Она создаёт два варианта, проверяет
исправленные варианты, выбирает более сильное подтверждённое объяснение и
использует фиксированный fallback, если evidence или ограничение 50–300
символов не проходят проверку. Этап комментариев не может изменить метку.

## Запуск

```bash
python3 -u run.py -i TEST_CSV -o SOLUTION_CSV
```

Обязательные входные поля:

- уникальный целочисленный `id`;
- `name`;
- `description`;
- `category` со значением `БАД` или `Легковоспламеняющиеся`.

Базовая модель загружается из
`${SHARED_MODELS_PATH:-/shared_models}/Qwen/Qwen3.5-4B`.

`--mock-inference` или `ECUP_MOCK_INFERENCE=1` проверяет только файловый
контур и не используется для production-предсказаний.

## Проверка целостности

`member_manifest.json` связывает каждый файл ZIP с размером и SHA-256.
`artifacts/production_manifest.json` связывает LoRA, CatBoost и базовую
модель. До inference runtime проверяет revision модели, hashes
классификационных prompts и comment-policy, token IDs и пороговые константы.

ZIP не содержит строки или метки organizer train.
